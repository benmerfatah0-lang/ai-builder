The pipeline

One sentence in. One structured world out.

Natural language never touches the renderer directly. It is interpreted into a versioned document, checked against the schema and against the scene itself, then built by procedural generators that know how a barn, a fence run or a wheat field should be made.

  1. Prompt

    Rules-based local interpreter detects biome, scale, time of day and farm features. Optional selects override size, style and density.

  2. WorldPlan v3

    Stable IDs, transforms, materials, dimensions, parent groups, generation metadata and placement hints — all in one JSON document.

  3. Validation

    Zod schema plus semantic checks: unsupported geometry, orphan parents, floating or buried objects, overlaps, missing dependencies.

  4. Generation

    A layout planner for farms and a seeded scatter generator for everything else. Deterministic, reproducible, budgeted.

  5. Assembly

    Real geometry: gabled roofs, board fences, crop instances, ribbon paths that follow the terrain, rivers and bridges.

  6. Editing

    The viewport builds only what changed. Edit, regenerate one object or a whole region, save to IndexedDB, export glTF.

Anatomy of the acceptance farm

Not one giant cube. Not a pile of primitives.

The brief asks for a farmhouse, a barn, wheat fields, a chicken coop, fences, trees and connected dirt paths. The planner lays them out in dependency order and keeps track of every footprint it has used.

Totals: 180 objects, 6 groups, ~91,500 triangles, 699 instanced props, 0 warnings and a clean validation report.

  • Silhouettes

    Barns have gable roofs and a hay door; the coop has a run; the silo is a cylinder with a cap. Each generator is a small composition, not a scaled box.

  • Proportions

    Dimensions live in the plan: 6.2 × 5.4 × 7.4 m barn, 3.4 × 4.3 × 3 m farmhouse. Placement, collision checks and the inspector all read the same numbers.

  • Materials

    Wall, roof, crop, soil, deck, rail and post colours are separate values per object, re-rolled by palette when you regenerate.

  • Relationships

    Buildings are grounded on sampled terrain, fields sit inside their fence, gates align with lanes, and the bridge only exists if a river does.

  • Overlap control

    An 8 m spatial hash rejects collisions between buildings, fields, fences and lanes while vegetation finds free ground around them.

  • Determinism

    The same prompt and seed always produce the same farm — down to which side of the yard the barn is on — so a shared JSON file reopens identically.

The editor

Generated, then edited like a Blender scene.

Generation is the starting point. The viewport, hierarchy and inspector are the same editor built in Phase 2 — the new objects simply arrive inside it, fully editable.

Orbit, pan, zoom, snap

OrbitControls and a transform gizmo with world/local space, snapping and axis constraints. Touch gestures included.

Hierarchy that survives edits

Rename, hide, lock, group, ungroup and reparent. Group transforms compose correctly; hide propagates down the tree.

Inspector with real values

Type exact position, rotation and scale. Change base, secondary, roughness, metalness and emission per object.

Regenerate, not rebuild

Re-roll a tree’s species and tint, a rock’s shape, a building’s palette or a field’s crop — alone or by region — without moving anything.

Local projects

IndexedDB autosave, project library, JSON import/export. Reopening a project restores transforms, hierarchy and generated metadata.

Export to engines

One shared scene builder feeds the viewport and a real binary glTF 2.0 exporter, so what you see is what you ship.

Validation & recovery

Nothing reaches the editor unchecked.

Two layers run on every plan: the document schema, then semantic checks against the scene itself. A failed step is reported, not hidden — and a damaged file can still be recovered.

Hard errors

  • schema — missing or mistyped fields, bad colours, out-of-range transforms
  • unsupported-geometry — declared and derived geometry ids checked against the registry
  • orphan-parent — an object pointing at a group that does not exist
  • missing-dependency — a bridge with no river to cross

Warnings worth reading

  • out-of-bounds objects near the terrain edge
  • floating more than 1.5 m, or buried more than 1.2 m
  • buildings overlapping by more than 0.2 m, fields by 0.5 m
  • a plan within 15% of the 1,500-object ceiling

Safe recovery

repairScenePlan drops unbuildable objects, re-grounds floaters and reports what it touched. Imports try strict parsing first, then lenient repair — with a warning rather than a blank screen.

Engineering

Modular by construction.

The WorldPlan document is the only source of truth. React never owns scene objects outside the viewport, and every hierarchy edit is a pure function over the document.

npm ci

npm run site:build  # demo bundle + editor build
npm test            # 113 tests
npm run typecheck

npm run render:preview regenerates the farm images from the scene graph with a software rasteriser.

Honest limits

What this is — and what it is not.

  • Not an LLM. The offline interpreter maps language cues to a structured intent. Unknown briefs fall back to the scatter generator rather than inventing features.
  • Farm layouts are curated. Seeded variation, mirroring and palettes keep them interesting, but this is a designed planner, not a general architecture solver.
  • WebGL is required for 3D. The site and the plan playground work without it; the viewport explains what to enable if a context cannot be created.
  • Device QA is ongoing. Rendering is unit-tested and previewed with a software rasteriser; physical desktop and Android testing remains manual.
