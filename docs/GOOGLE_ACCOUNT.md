# ربط حساب Google وحفظ مفتاح API

> الميزة تحتاج إلى **خادم تتحكم به** وحساب Google Cloud لإعداد تسجيل الدخول.
> الملف HTML المفرد الذي يُشغَّل بخادم Python وحده لا يستطيع حفظ المفتاح أو
> مزامنته بين الأجهزة. إعدادات Google والخادم غير مفعّلة تلقائياً في المعاينة.
> لا ترسل مفاتيحك أو كلمات المرور في المحادثة.

## ماذا يحدث للمفتاح؟

بعد تسجيل الدخول، تضغط «حفظ في الحساب». يحفظ خادم التطبيق المفتاح مشفّراً
بـ AES-256-GCM، ويربطه بمعرّف Google الخاص بك. **لا يُحفظ داخل Gmail أو
مشاريعك**، ولا يعيده الخادم إلى المتصفح. طلبات الذكاء الاصطناعي تمر عبر
الخادم الذي يفك تشفير المفتاح ويرسله إلى OpenAI. يستطيع مشغّل الخادم الذي
يمتلك سر التشفير فكّه، لذلك استخدم خادماً موثوقاً فقط. تستطيع حذف المفتاح
من الواجهة في أي وقت؛ حذف المفتاح لا يمس حساب OpenAI نفسه.

## إعداد Google

1. أنشئ مشروعاً في Google Cloud وأعدّ شاشة موافقة OAuth. إذا كان التطبيق في
   وضع الاختبار فأضف حسابك إلى مستخدمي الاختبار.
2. أنشئ OAuth Client من نوع **Web application**.
3. أضف عنوان إعادة توجيه مطابقاً تماماً:
   `https://YOUR_DOMAIN/api/auth/google/callback`، أو للتجربة على الجهاز نفسه
   `http://localhost:5173/api/auth/google/callback` عند تشغيل Vite.
4. احتفظ بمعرّف العميل وسر العميل في إعدادات الخادم الخاصة، وليس في ملفات
   عامة أو المحادثة.

## تشغيل الخادم

ثبّت Node.js 20.19+ أو 22.12+ ثم نفّذ `npm ci` و `npm run build`. ضع الإعدادات
في بيئة الخادم أو في ملف `.env` محلي غير مرفوع إلى Git:

```dotenv
APP_ORIGIN=https://YOUR_DOMAIN
GOOGLE_CLIENT_ID=your-client-id
GOOGLE_CLIENT_SECRET=your-client-secret
SESSION_SECRET=your-long-random-secret
KEY_ENCRYPTION_SECRET=your-base64-32-byte-key
DATA_DIR=/path/to/private-persistent-data
TRUST_PROXY=1
PORT=8787
```

`APP_ORIGIN` هو أصل الموقع فقط بلا `/` في النهاية. HTTPS مطلوب إلا على
`localhost` أو `127.0.0.1` للتجربة المحلية. `SESSION_SECRET` يجب ألا يقل عن
32 حرفاً، و `KEY_ENCRYPTION_SECRET` يجب أن يكون 32 بايت عشوائياً مشفّراً بـ
base64. يمكن توليد كل منهما محلياً باستخدام:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

شغّل الخادم في المجلد الرئيسي بعد إعداد البيئة:

```bash
node --env-file=.env --import tsx server/index.ts
```

يفتح الخادم بناء التطبيق من `dist/` ويخدم `/api` من نفس الأصل. في التطوير،
شغّل الخادم ثم `npm run dev`؛ يمرر Vite طلبات `/api` إلى المنفذ 8787.
`TRUST_PROXY=1` ضروري فقط خلف وكيل HTTPS موثوق واحد. لا تعرض الخادم مباشرة
خلف وكيل غير موثوق، واستخدم جدار حماية وTLS وأسراراً مختلفة لكل نشر.

للمزامنة بين الأجهزة، يجب أن تفتح جميعها **نفس عنوان HTTPS العام** الذي
يسير إلى نفس الخادم، وأن يكون `DATA_DIR` على وحدة تخزين دائمة خاصة خارج
المجلد العام وGit. هذا تنفيذ لخادم واحد فقط؛ لا تدعم ملفات التخزين وجلسات
الذاكرة التشغيل المتعدد، وتسجيل الدخول ينتهي عند إعادة تشغيل الخادم. يحتاج
النشر العام إلى تخزين جلسات دائم، نسخ احتياطية مشفّرة، إدارة أسرار ومراجعة
أمنية. لا تغيّر سر التشفير دون خطة ترحيل وإلا يتعذّر قراءة المفاتيح القديمة.
إذا لم يكتمل الإعداد، تعرض الواجهة رسالة واضحة وتبقى ميزة الحساب معطّلة.
